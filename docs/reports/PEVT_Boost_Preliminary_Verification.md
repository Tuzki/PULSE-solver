# PULSEES1 与 Boost 初步验证

日期：2026-11-02。范围：按用户协议实现原生事件输出，仅以完整 C002 Boost 做初步验证；A010 与全案例批测保持暂停。

## 实现

协议原件与仓库 [Event_Stream_Format.md](../Event_Stream_Format.md) SHA256 一致。新增原生 `.pevt` 写入、读取和波形重建，Windows/Linux 共用实现。每个事件引用一个完整状态切片，保存完整前、后元件模态 ID、方程 ID、精确 T128 时间及 Flow 原点引用。详细字段与命令见 [实现说明](../PEVT_Implementation.md)。

改动位于 `src/pevt.cpp`、`include/pulse/pevt.hpp`、trajectory/runtime 归档接线、Flow 原点元数据、跨平台缓冲区 SHA256、CMake 和测试。保持原状态传播、事件定位、数值策略、容差、网表与控制器。

## 环境与测试

Windows 原生 GCC 16.2；Linux 为 WSL2 Ubuntu 24.04、GCC 13.3、原生 x86-64 ELF 和 `.so` 控制器。两端 long double 有效二进制位为 64，指数上限 16384。读取器校验归档数值上下文。

|---|---:|---:|---:|---:|---:|
| Windows | 26 | 26 | 0 | 0 | 23.49 s |
| Linux | 26 | 26 | 0 | 0 | 11.53 s |

覆盖现有原生测试、软件域 ABI/控制器、RC/Buck/Boost 事件状态与模态、逐位波形重建、SHA256 损坏、截断、非法引用、精度上下文及非有限值拒绝。独立 Python 解析器也校验两个完整 Boost 文件全部数据段与引用。

## 完整 Boost 用时和文件

使用案例库原始 `rohm-c002-d-boost/pulse/netlist.md` 与 `controller.c`，T_END=0.3 s，SAVE_DT=0.2 µs。输入、参考 CSV 和可执行文件 SHA256 见 [证据](PEVT_Boost_Preliminary_Verification_Evidence.json)。

## 精度

Windows、Linux 各自新格式重建与原 PULSE 的时间数组和全部 7 路波形数组逐位一致；事件日志 SHA256 一致。所检查的终止状态、内部/物理状态、软件状态/输出、事务、根查询、模态编译、回滚和矩阵指数计数均一致。Windows/Linux 对应波形数组也逐位一致。容器文件包含不同元数据，文件整体 SHA256 无须相同。

本轮实时 PLECS 输出与案例库原始 CSV 的时间和全部数值逐位一致。四组 PULSE 波形对原始 PLECS 全时段参考网格比较均为 **20/21**；统计量为各通道 mean/rms/max，阈值为 provenance atol + 1% × |参考值|。这是初步全时段统计检查，不代替历史窗口验收。
