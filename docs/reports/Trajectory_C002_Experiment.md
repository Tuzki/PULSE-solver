## 本轮同会话、同口径结果

硬件为 AMD Ryzen 5 6600H；PULSE 两版与重放均在本机 WSL2 Ubuntu 24.04.5
x86-64 下运行；PLECS 为本机 Windows 4.8.2。GCC 13.3、Release，原有严格浮点
选项不变。原版和改版运行各使用新目录，没有并行仿真，没有取多次最优值。

统一使用 Windows 主机 Python `time.perf_counter()`：开始仿真指令发出，至程序
完成通知收到。PLECS 以同步 simulate API 返回为完成通知；PULSE 以 CLI 根级
`status: COMPLETED` 行被收到为完成通知。这是按钮动作的程序触发等价口径，
没有声称测量真实鼠标/UI 分发延迟。安装、编译和模型文档加载在计时前完成；
PULSE CLI 启动、网表解析、实际求解和结果写出在其计时内。

| 程序/阶段 | 本轮耗时 | 产物 |
|---|---:|---|
| PLECS 4.8.2（Windows） | **10.033216300 s** | 完整 0.3 s 参考输出，原有 1 us 捕获网格 |
| 原 PULSE（Linux） | **30.999158300 s** | 原 0.2 us 网格的完整波形及事件日志 |
| 改版 PULSE：轨迹生成（Linux） | **10.937649100 s** | 完整连续轨迹及事件日志，尚未物化密集波形 |
| 改版：完整波形重放（Linux） | **25.639064200 s** | 重建原 0.2 us 网格、1,500,001 点完整波形 |
| 改版：轨迹生成＋完整重放 | **36.576713300 s** | 两阶段合计，提供与原版相同采样数据 |

轨迹生成较原版约 **2.834 倍**提速，完成通知耗时约为 PLECS 的 **1.090 倍**。
如果每次都立即物化全部波形，两阶段合计则为原版的 **1.180 倍**，约慢 **18.0%**。
因此本实验验证了延后生成密集输出的收益，**没有证明完整波形导出端到端变快**。
PLECS 与 PULSE 的原输出网格不同，本次保持原配置，没有通过改采样参数提高速度。

这组本机数据独立于此前的 64.768 s / 19.875 s 对照和 139.173 s 单次记录，
不跨轮次拼接，也不与 GitHub CI 环境计时混用。

## 修改范围和限制

运行时仅在原事务接受/提交位置选择“原采样输出”或“轨迹记录”。
`engineering_flow.cpp` 只添加只读锚点/Mode/偏移访问器及调用原构造器的恢复接口；
没有改动原有传播、根定位、联合事件、LU/QR、坐标或容差代码。
采样有限性/float32 范围/容量检查复用原有 `stream_emit/stream_commit`，在重放阶段
执行，并明确标记 `DEFERRED_TO_REPLAY` 与 `PASSED`，不混淆物理轨迹完成和波形校验完成。

v1 使用原 Flow 构造器重建派生缓存，保存原始内部锚点和完整 T128 偏移；
不把公开物理快照当作新的数值锚点。模板/记录带 SHA256 校验，重放要求匹配
long double 精度。本次认证范围是本 Linux 构建，跨编译器位级重放未认证。
实验版每个流文件有 64 MiB 限制；它不是通用仿真恢复/续跑格式。
