# A010 事件归档膨胀缺陷调查

2026-11-02。按用户指示停止 Windows/Linux 的 A010 PULSE 和全案例批测。
此次只离线读取已生成的归档，没有再次运行 A010 求解器。

这是 v1 阶段的历史记录。后续 v2 已修复存储膨胀，但 CPU 重复工作仍然存在；
最新进度、采样根因和完整验证边界见 [A010 根因调查](A010_Root_Cause_Analysis.md)。

## 结论

事件格式 v1 的模板去重粒度过粗：`Trajectory::mode()` 对完整 `Mode`
进行 `encode()` 和 `dump()`，把整个 JSON 字符串作为去重键。
任何观测映射、控制保持值、数值策略或其他字段变化，都会再次保存整套
矩阵、映射、约束、残差和守卫数据。大部分内容相同也无法共享。

这属于实验事件归档实现的缺陷，不能将 1 GB 模板解释为正常的事件数据量，
也不能只放大文件上限作为解决办法。未发现此处增加了物理事件；本调查
没有修改事件发现、模态转换、控制器、数值策略或容差。

## 实际证据

Windows A010 原版在原厂 0.5 s 终点 COMPLETED：159,037 次事务、
315,096 条事件记录、152,180 次模态编译。这些数量来自原版报告，
不是事件归档新增的事务数。Windows 与 Linux 原版完整运行已保留。

Windows 事件版报告物理求解到 0.5 s，但文件封装失败，CLI 返回 1，
没有成功通知；其后回放也失败。**不能把磁盘报告中的 COMPLETED
当成事件输出或波形回放通过。** 批测工具已补充这一判据。

| Windows 事件版文件 | 实际字节数 |
|---|---:|
| templates.json | 1,054,309,089 |
| segments.bin | 45,802,800 |
| event_log.jsonl | 109,069,186 |

模板总数为 **92,893**。`templates.json` SHA256：
`24d8bd3802de6352f67427e69726d5872a82fa284fdf369ac8c3bbea89621c41`。

相邻模板 1→2 仅改变以下两个标量，却再次保存约 10 KB 完整模板：

- `/maps/MODULATION/data/4`
- `/residual_reference/data/372`

## 前 10,000 份模板的分项调查

下表的字段体积为紧凑 JSON 统计，不含外层键名/分隔符；独立字段去重
使用 SHA256 统计，候选块共享原型使用实际二进制内容相等来去重。

| 字段 | 累计 JSON 字节 | 不同字段值数量 | 不同值仅保存一次的字节 |
|---|---:|---:|---:|
| maps | 66,118,008 | 10,000 | 66,118,008 |
| residual_map | 19,000,156 | 19 | 35,640 |
| residual_reference | 15,922,950 | 2,377 | 3,784,639 |
| guards | 6,182,825 | 20 | 12,260 |
| M | 2,329,796 | 10 | 2,284 |
| bools | 433,155 | 7 | 305 |

尤其是 **10,000 份完整模板只有 10 个不同的 M 矩阵**。
`maps` 整体虽每份不同，其大量名称、行向量和标量仍然重复；因此还需要
在字段内部共享相同块，不能仅按整个 `maps` 对象去重。

## 离线无损共享原型

新增 `scripts/audit_trajectory_templates.py`，只读取归档，不调用求解器。
它将类型明确的二进制标量、字符串和分块数组按完全相同的内容共享，
使用索引引用；不按浮点容差合并，不舍入，不删除 Mode 字段。

| 项目 | 实测/检查结果 |
|---|---:|
| 抽样原始模板对象字节 | 113,306,928 |
| 候选共享块 + 模板根索引 + 估计头部字节 | 4,447,456 |
| 占抽样原对象体积 | 3.925% |
| 无损编码/还原并比较的模板 | 10,000 |
| 还原差异 | 0 |
| +0 / -0、相差 1 ULP 的数值及长数组检查 | 通过 |

这是离线存储原型结果，**尚未接入 C++ 求解器，不能当作完整新格式的
文件大小、内存占用、仿真提速或 Windows/Linux 验证结果**。
模板以外的 109 MB 原 JSONL 事件日志也没有因此缩小。

复现离线调查（输入为已保留的归档文件，不启动 A010 仿真）：

```powershell
python scripts/audit_trajectory_templates.py <已有归档>/templates.json --sample 10000 --out <新目录>/audit.json
```

机器可读结果：[Trajectory_Template_Bloat_Evidence.json](Trajectory_Template_Bloat_Evidence.json)。

## 处理状态与后续边界

- 已停止 Windows/Linux A010；最终检查无 `pulse-solver` 进程。
- Linux 首轮事件版在调查时被停止，不宣称其完成时刻或精度通过；停止前
  一次观测 RSS 为 6,484,212 KiB。既有 Windows 归档及两平台原版结果保留。
- 尚未验证“分块 SHA256 + 更大归档上限”的草稿已备份并撤回，未作为修复部署。
  模块原有校验和大小上限没有关闭。
- 正确修复应先改变归档共享粒度，精确保留所有不同数值，再处理大事件日志的
  流式校验与明确资源上限。不能按拓扑相同或数值近似而强行复用整个 Mode。
- 新格式接入后需要版本标识、索引/截断/完整性检查，以及原版对新回放的逐字节
  波形和状态一致性测试。在此之前不恢复 A010 全时长试跑。
- 20 案例跨平台比较尚未完成；没有发布全案例 PASS 或最终性能表。
