# Stage C / D：A010 50 ms 运行时重复计算审计

日期：2026-11-04。只统计执行次数、申请字节量、完整输入重复及复用；没有采集或比较墙钟、CPU 时间、CPU 占比，没有 CPU sampling。排序表示重复证据和结构性改造优先级，不表示耗时排名。

## 结论

Stage D 的确消除了本窗口内测到的重复完整绑定矩阵计算，以及同锚点的重复 24 阶状态递推。但没有消除临时 Flow 的公共初始化、观察行的静态投影准备、Flow 兼容性比较的隐式矩阵临时对象，或 PEVT 的结构重比。

另发现一个具体的结构性抵消项：D 的 rebound 缓存持有 Binding 后，portfolio_compile 的坐标适配写入触发新的 COW 深复制。该路径从 C 的 **24 次**增长至 D 的 **41,234 次**，产生 **7,504,588 次申请、678,051,896 B** 的累计申请量。该数不是 CPU 时间，也不是峰值内存。

未修改 Release 程序的公开申请总数从 **61,439,531 降至 48,260,812，减少 21.4499%**；累计申请量从 **7,538,085,240 B 降至 5,013,901,499 B，减少 33.4857%**。仍有约 **2,734 次申请/事务**。

## 测量方法及计数器校核

1. 函数/分支/循环操作计数在独立源码副本中加入；包含原本会内联的操作，不把外部符号出现次数当作总调用次数。循环行/单元数按实际执行路径的完整循环长度累计，成功路径没有提前退出。
2. 分配按主要逻辑作用域记录，不采样调用栈；路径有父子关系。ALLOC_PATHS.csv 的各行是互斥叶作用域的分配，不能再加父作用域的包含统计。按值参数和构造初始化列表可能计入调用者。
3. 矩阵键包含形状和全部 binary64 字节，先完整核对 A/N/B，再统计实际计算的输入组合；不是哈希相同即命中。Taylor 键包含不可变 Basis、原始锚点和 local_rate；Flow 公共前缀用 Basis+原始锚点；静态投影用 Basis+完整 row。原有 Basis 值缓存持有全部 10 个对象，身份在进程内不会释放重用。
4. 工具查重产生的分配、释放、哈希和最终 JSON 输出均排除。最终记录另列工具自身累计申请量。只支持本次实测的单线程；线程数不为 1 或表溢出即拒绝验收。两版最终均 1 线程、0 溢出、0 分配失败。
5. 校准用例明确验证 malloc(17)、calloc(3,7)、realloc(33)、两次有效 free 及 free(NULL)，并验证相同键重复/不同键区分。最初自检发现工具临时字符串在退出抑制区后析构，被错误计入一次 free；已用 RAII 覆盖整个工具临时对象生命周期，修复后才运行正式计数。
6. 插桩影响编译器将分配+清零合并为 calloc、消除 free(NULL) 的机会。因此 **malloc/calloc/realloc/free 的权威值来自未修改 Release ELF 的 allocation-only 拦截**。源码计数只用于细分路径与操作次数。
7. 未修改 ELF 与最终源码计数的 malloc+calloc+realloc 合计，每版仅差 **4 次、194 B**；nonnull free 也差 4 次。单独的 malloc/calloc 分类和 free(NULL) 会有明显差异，完整保留在 JSON，不能将其当作原始 Release API 分布。

计数范围是观察器初始化后至退出输出前的公开 API 请求，包含初始化、仿真、归档写出与清理；不包括直接 mmap 或 glibc 私有内部接口。字节是累计请求量，realloc 按完整新大小计，不是存活内存、RSS 或拷贝字节量。原求解器自动生成的 run_seconds 等字段仍在本地原始日志中，本轮没有将其作为测量结果提取、分析或比较。

### 新发现：坐标适配重新触发 Binding 深复制

实际路径是 simulate → portfolio_compile → CowValue<ModeBinding>::edit → detach，不是猜测 state copy 的来源：

| 深分离所在路径 | C | D |
|---|---:|---:|
| bind 内 | 41,212 | 17,784 |
| observe 临时视图 | 36,174 | 0 |
| portfolio_compile 坐标转换 | 24 | 41,234 |
| 合计 | 77,410 | 59,018 |

D 在 descriptor.cpp 的 rebound_entries 中保存不可变绑定模板。返回的 Mode 与缓存共享 Binding；solver_strategy.cpp:12 的 portfolio_compile 随后在 raw 策略分支变换 observations、residual_map、residual_reference、maps、guards，第一次 edit 触发全 Binding 复制。C 的即时绑定通常已唯一持有，所以该适配基本不再分离。

这是缓存存储的坐标层与实际使用的坐标层没有统一造成的重复物化。可研究按 Model、策略、坐标图及完整动态输入缓存最终不可变绑定视图；每次新物理状态的检查仍必须执行。不能简单删掉 edit、坐标变换或状态检查。
